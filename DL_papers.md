# Embeddings / Positional Encodings

1. **Attention Is All You Need** (Vaswani et al., 2017) — [arXiv:1706.03762](https://arxiv.org/abs/1706.03762) — **PE**
   Sinusoidal absolute encoding added at the input; PE(p+k) is a rotation of PE(p).
2. **Self-Attention with Relative Position Representations** (Shaw, Uszkoreit, Vaswani, 2018) — [arXiv:1803.02155](https://arxiv.org/abs/1803.02155)
   First relative scheme: learned embeddings of clipped offset j−i injected into attention.
3. **Transformer-XL** (Dai et al., 2019) — [arXiv:1901.02860](https://arxiv.org/abs/1901.02860)
   Sinusoidal relative terms + global u, v biases; relative position is what makes segment recurrence work.
4. **RoFormer: Enhanced Transformer with Rotary Position Embedding** (Su et al., 2021) — [arXiv:2104.09864](https://arxiv.org/abs/2104.09864) — **RoPE**
   Rotate q, k so that ⟨R_m q, R_n k⟩ = ⟨q, R_{n−m} k⟩; the default in modern LLMs.
5. **ALiBi: Train Short, Test Long** (Press et al., 2021) — [arXiv:2108.12409](https://arxiv.org/abs/2108.12409)
   No embeddings at all: a per-head linear distance penalty on the logits; built for length extrapolation.
6. **YaRN** (Peng et al., 2023) — [arXiv:2309.00071](https://arxiv.org/abs/2309.00071)
   Frequency-dependent RoPE interpolation + attention temperature; the practical recipe for extending context.
7. **Round and Round We Go! What makes Rotary Positional Encodings useful?** (Barbero et al., 2024) — [arXiv:2410.06205](https://arxiv.org/abs/2410.06205)
   Distance decay is not why RoPE works; high frequencies build positional heads, low frequencies carry semantics.
8. **Rethinking RoPE: A Mathematical Blueprint for N-dimensional Positional Encoding** (2025) — [arXiv:2504.06308](https://arxiv.org/abs/2504.06308)
   Valid RoPEs ↔ bases of a maximal abelian subalgebra (MASA) of so(n); standard RoPE = maximal torus.

### 1. Precursors

- **End-To-End Memory Networks** (Sukhbaatar et al., 2015) — [arXiv:1503.08895](https://arxiv.org/abs/1503.08895) — first use of the term "position encoding": fixed multiplicative weights on word embeddings in a bag-of-words memory.
- **Convolutional Sequence to Sequence Learning** (Gehring et al., 2017) — [arXiv:1705.03122](https://arxiv.org/abs/1705.03122) — learned absolute position embeddings; the learned baseline Vaswani et al. compared against.

### 2. Absolute PE

- **Attention Is All You Need** (Vaswani et al., 2017) — [arXiv:1706.03762](https://arxiv.org/abs/1706.03762) — **PE** — sinusoidal, additive at input.
- **BERT** (Devlin et al., 2018) — [arXiv:1810.04805](https://arxiv.org/abs/1810.04805) — learned absolute table with a hard max length; the encoder-era default.
- **Encoding Word Order in Complex Embeddings** (Wang et al., ICLR 2020) — [arXiv:1912.12333](https://arxiv.org/abs/1912.12333) — each word is a complex function of position r·e^{i(ωp+θ)}; sinusoidal PE falls out as a simplified case. Conceptual ancestor of RoPE.
- **FLOATER** (Liu et al., ICML 2020) — [arXiv:2003.09229](https://arxiv.org/abs/2003.09229) — position embeddings generated by a neural ODE; sinusoidal PE is a special case.
- **TUPE: Rethinking Positional Encoding in Language Pre-training** (Ke et al., ICLR 2021) — [arXiv:2006.15595](https://arxiv.org/abs/2006.15595) — removes word↔position cross terms in attention; separate projections for position.

### 3. Relative PE (inside attention)

- **Self-Attention with Relative Position Representations** (Shaw, Uszkoreit, Vaswani, 2018) — [arXiv:1803.02155](https://arxiv.org/abs/1803.02155) — learned embeddings of clipped offset j−i added to keys (and values).
- **Music Transformer** (Huang et al., 2018) — [arXiv:1809.04281](https://arxiv.org/abs/1809.04281) — "skewing" trick: relative attention in O(Ld) memory instead of O(L²d).
- **Transformer-XL** (Dai et al., 2019) — [arXiv:1901.02860](https://arxiv.org/abs/1901.02860) — sinusoidal relative terms + global u, v biases.
- **T5** (Raffel et al., 2019) — [arXiv:1910.10683](https://arxiv.org/abs/1910.10683) — a learned scalar bias per head per log-spaced distance bucket.
- **DeBERTa** (He et al., 2020) — [arXiv:2006.03654](https://arxiv.org/abs/2006.03654) — disentangled attention with separate content→position and position→content terms.

### 4. Rotary / multiplicative PE

- **RoFormer** (Su et al., 2021) — [arXiv:2104.09864](https://arxiv.org/abs/2104.09864) — **RoPE** — ⟨R_m q, R_n k⟩ = ⟨q, R_{n−m} k⟩.
- **xPos: A Length-Extrapolatable Transformer** (Sun et al., 2022) — [arXiv:2212.10554](https://arxiv.org/abs/2212.10554) — RoPE × exponential decay for extrapolation.
- **Round and Round We Go!** (Barbero et al., ICLR 2025) — [arXiv:2410.06205](https://arxiv.org/abs/2410.06205) — RoPE's usefulness is not distance decay; in Gemma 7B high frequencies serve positional heads, low frequencies semantic matching.
- **LieRE: Generalizing Rotary Position Encodings** (Ostmeier et al., 2024) — [arXiv:2406.10322](https://arxiv.org/abs/2406.10322) — positions → learned skew-symmetric generators, R = exp(P); full SO(n) instead of 2×2 blocks.
- **Rethinking RoPE: A Mathematical Blueprint for N-dimensional PE** (2025) — [arXiv:2504.06308](https://arxiv.org/abs/2504.06308) — valid RoPEs ↔ bases of a MASA of so(n); standard RoPE = maximal toral subalgebra.
- **STRING: Learning the RoPEs** (Schenck et al., ICML 2025) — [arXiv:2502.02562](https://arxiv.org/abs/2502.02562) — commuting skew-symmetric generators → separable, translation-invariant 2D/3D encodings (vision, robotics).
- **GRAPE: Group Representational Position Encoding** (ICLR 2026) — [arXiv:2512.07805](https://arxiv.org/abs/2512.07805) — group-action framework built on the exact relative law G(t−s) = G(s)ᵀG(t).
- **PaTH Attention** (Yang et al., NeurIPS 2025) — [arXiv:2505.16381](https://arxiv.org/abs/2505.16381) — data-dependent cumulative products of Householder-like matrices; provably lifts transformers beyond TC⁰ (assuming TC⁰ ≠ NC¹).

### 5. Attention biases & length extrapolation

- **ALiBi: Train Short, Test Long** (Press et al., ICLR 2022) — [arXiv:2108.12409](https://arxiv.org/abs/2108.12409) — no embeddings; per-head linear distance penalty.
- **KERPLE** (Chi et al., NeurIPS 2022) — [arXiv:2205.09921](https://arxiv.org/abs/2205.09921) — biases from conditionally positive definite kernels of distance; ALiBi is one instance.
- **FIRE** (Li et al., ICLR 2024) — [arXiv:2310.04418](https://arxiv.org/abs/2310.04418) — learned MLP of normalised distance (progressive interpolation); provably represents T5 RPE, ALiBi and KERPLE.
- **Randomized Positional Encodings** (Ruoss et al., ACL 2023) — [arXiv:2305.16843](https://arxiv.org/abs/2305.16843) — train on ordered random subsets of a larger position range so long positions aren't out-of-distribution.
- **CoPE: Contextual Position Encoding** (Golovneva et al., 2024) — [arXiv:2405.18719](https://arxiv.org/abs/2405.18719) — position increments only on model-selected tokens; can address "the i-th sentence/noun".

### 6. No positional encoding (NoPE)

- **Transformer LMs without Positional Encodings Still Learn Positional Information** (Haviv et al., 2022) — [arXiv:2203.16634](https://arxiv.org/abs/2203.16634) — the causal mask alone leaks position in decoders.
- **The Impact of Positional Encoding on Length Generalization** (Kazemnejad et al., NeurIPS 2023) — [arXiv:2305.19466](https://arxiv.org/abs/2305.19466) — NoPE length-generalises better than PE/RoPE/ALiBi on algorithmic tasks.
- **RoPE to NoPE and Back Again** (Yang et al., NeurIPS 2025) — [arXiv:2501.18795](https://arxiv.org/abs/2501.18795) — RNoPE: interleave NoPE and RoPE layers.

### 7. Context extension for RoPE models

- **Position Interpolation** (Chen et al., 2023) — [arXiv:2306.15595](https://arxiv.org/abs/2306.15595) — linearly downscale position indices into the trained range.
- **YaRN** (Peng et al., 2023) — [arXiv:2309.00071](https://arxiv.org/abs/2309.00071) — frequency-dependent interpolation ("NTK-by-parts") + attention temperature.
- **Effective Long-Context Scaling of Foundation Models** (Xiong et al., 2023) — [arXiv:2309.16039](https://arxiv.org/abs/2309.16039) — adjusted base frequency (ABF) in Llama 2 Long.
- **Scaling Laws of RoPE-based Extrapolation** (Liu et al., 2023) — [arXiv:2310.05209](https://arxiv.org/abs/2310.05209) — both larger and smaller bases can improve extrapolation after fine-tuning; "critical dimension" explanation.
- **LongRoPE** (Ding et al., 2024) — [arXiv:2402.13753](https://arxiv.org/abs/2402.13753) — searched non-uniform per-dimension rescaling; ~2M tokens.
- **Base of RoPE Bounds Context Length** (Men et al., NeurIPS 2024) — [arXiv:2405.14591](https://arxiv.org/abs/2405.14591) — absolute lower bound on the base for a target context length; below it, long-context ability is only superficial.
- *Note:* NTK-aware scaling (bloc97, 2023) started the base-rescaling line — a Reddit post, not a paper.

### 8. Beyond 1D: vision & multimodal

- **ViT** (Dosovitskiy et al., 2020) — [arXiv:2010.11929](https://arxiv.org/abs/2010.11929) — learned 1D absolute over patches, interpolated for new resolutions.
- **CPVT: Conditional Positional Encodings** (Chu et al., 2021) — [arXiv:2102.10882](https://arxiv.org/abs/2102.10882) — PE generated by a convolution over each token's local neighbourhood.
- **Rotary Position Embedding for Vision Transformer** (Heo et al., 2024) — [arXiv:2403.13298](https://arxiv.org/abs/2403.13298) — 2D axial RoPE and RoPE-Mixed (learned frequencies).
- **Qwen2-VL** (2024) — [arXiv:2409.12191](https://arxiv.org/abs/2409.12191) — M-RoPE: rotary dims split across time / height / width.
- See also LieRE and STRING in §4.

### 9. Related: Fourier features

- **Fourier Features Let Networks Learn High Frequency Functions in Low Dimensional Domains** (Tancik et al., 2020) — [arXiv:2006.10739](https://arxiv.org/abs/2006.10739) — NTK explanation of why sinusoidal input maps work.
- **NeRF** (Mildenhall et al., 2020) — [arXiv:2003.08934](https://arxiv.org/abs/2003.08934) — the same γ(p) "positional encoding" for continuous coordinates.

# Optimizations / KV Cache, MQA, MLA, FlashAttention

1. **Online normalizer calculation for softmax** (Milakov & Gimelshein, 2018). [arXiv:1805.02867](https://arxiv.org/abs/1805.02867)
   Softmax in a single pass, using a running maximum and normalizer. FlashAttention is built on this trick.
2. **Fast Transformer Decoding: One Write-Head is All You Need** (Shazeer, 2019). [arXiv:1911.02150](https://arxiv.org/abs/1911.02150) **MQA**
   Shows that decoding is limited by memory bandwidth, and shares one K/V head across all query heads.
3. **FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness** (Dao et al., 2022). [arXiv:2205.14135](https://arxiv.org/abs/2205.14135)
   Exact attention computed in tiles held in SRAM, so the N×N matrix is never written to HBM. Memory grows as O(N).
4. **Efficiently Scaling Transformer Inference** (Pope et al., 2022). [arXiv:2211.05102](https://arxiv.org/abs/2211.05102)
   The standard analysis of inference cost: time spent moving memory vs. computing, how to partition the model, and the KV cache at PaLM scale.
5. **GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints** (Ainslie et al., 2023). [arXiv:2305.13245](https://arxiv.org/abs/2305.13245) **GQA**
   g KV groups, in between MHA and MQA. Also shows how to "uptrain" an existing MHA checkpoint into GQA.
6. **FlashAttention-2** (Dao, 2023). [arXiv:2307.08691](https://arxiv.org/abs/2307.08691)
   Parallelizes over sequence length, cuts work that isn't matrix multiplication, and splits work across warps better. Roughly 2× faster than FlashAttention-1.
7. **Efficient Memory Management for LLM Serving with PagedAttention** (Kwon et al., 2023). [arXiv:2309.06180](https://arxiv.org/abs/2309.06180) **vLLM**
   Stores the KV cache in fixed-size blocks with a block table, the way an OS pages memory, so almost no memory is wasted to fragmentation.
8. **DeepSeek-V2** (DeepSeek-AI, 2024). [arXiv:2405.04434](https://arxiv.org/abs/2405.04434) **MLA**
   Keys and values are jointly compressed into one low-rank latent that is cached. The up-projections are folded into the query and output matrices, and a separate RoPE key handles position.

### 0. Why this matters

**Decoding is limited by memory bandwidth.** Each new token requires reading all the weights and the whole KV cache from HBM. The KV cache per token is:

> bytes/token = 2 · n_layers · n_kv_heads · d_head · bytes_per_element

*Example:* Llama-3-70B has 80 layers, 8 KV heads (GQA), d_head = 128, in bf16. That is 320 KiB per token, or about 40 GiB for one 128K-token sequence. Full MHA with 64 KV heads would need 8× that.

**The cache has five dimensions, and most methods shrink one of them:**

| Dimension of the KV cache | Methods | Section |
|---|---|---|
| KV heads | MQA, GQA | §2 |
| head dim / rank | MLA, TPA, GLA | §3 |
| layers | CLA, YOCO | §4 |
| tokens | StreamingLLM, H2O, SnapKV, NSA, MoBA, DSA | §5 |
| bits | KIVI, KVQuant | §6 |

How the cache is **stored** (§7: paging, prefix sharing, disaggregation) and how attention over it is **computed** (§8: the FlashAttention family) are separate questions from the table above.

**Arithmetic intensity.** During decoding, each KV head is loaded once and used by every query head that shares it. So FLOPs per byte grow with the number of query heads per KV head. MQA, GQA and MLA (in its absorbed form) make decoding faster for this reason, not only because they shrink the cache.

**The algebra behind FlashAttention.** For one query, the softmax-attention partial state over a set of keys is s = (m, ℓ, o): m is the maximum logit, ℓ = Σ e^{x−m}, and o = Σ e^{x−m}·v. Two states combine as follows:
m = max(m₁, m₂), ℓ = ℓ₁e^{m₁−m} + ℓ₂e^{m₂−m}, o = o₁e^{m₁−m} + o₂e^{m₂−m}, and the final output is o/ℓ.
This merge ⊕ is associative and commutative, with identity (−∞, 0, 0), so the states form a **commutative monoid**. Any order of reduction gives the same answer. That is why the same idea works for tiling (FlashAttention), splitting the KV cache within a GPU (Flash-Decoding), splitting it across GPUs (Ring Attention), and composing cache formats (FlashInfer's attention-state ⊕).

**Where positional encoding comes in.** RoPE rotates each key by a matrix that depends on its position, so the key up-projection can no longer be folded into the query projection. This is why MLA needs a *decoupled* RoPE key. See the positional-encodings notes.

### 1. Foundations: what inference costs

- **Efficiently Scaling Transformer Inference** (Pope et al., 2022). [arXiv:2211.05102](https://arxiv.org/abs/2211.05102). Separates time spent on memory from time spent on compute, gives partitioning layouts, and works through the trade-off between latency and batch size.
- **Orca** (Yu et al., OSDI 2022, not on arXiv). Introduced scheduling per decoding step (iteration-level), now called *continuous batching*.
- **A Survey on Efficient Inference for Large Language Models** (Zhou et al., 2024). [arXiv:2404.14294](https://arxiv.org/abs/2404.14294)

### 2. Fewer KV heads

- **MQA** (Shazeer, 2019). [arXiv:1911.02150](https://arxiv.org/abs/1911.02150). One K/V head shared by all query heads.
- **GQA** (Ainslie et al., 2023). [arXiv:2305.13245](https://arxiv.org/abs/2305.13245). g groups of query heads, each group with its own K/V head. An MHA checkpoint is converted by mean-pooling its K/V heads within each group and then training briefly.

### 3. Low-rank / latent KV

- **DeepSeek-V2** (2024). [arXiv:2405.04434](https://arxiv.org/abs/2405.04434). **MLA.** Caches only the latent c_t^{KV} plus a separate RoPE key, (d_c + d_h^R) elements per layer. With d_c = 4d_h and d_h^R = d_h/2, that is the same cache size as GQA with 2.25 groups.
- **DeepSeek-V3** (2024). [arXiv:2412.19437](https://arxiv.org/abs/2412.19437). MLA at 671B scale.
- **TransMLA** (Meng et al., 2025). [arXiv:2502.07864](https://arxiv.org/abs/2502.07864). Proves that any GQA layer can be written as MLA with the same KV cache size, but not every MLA layer can be written as GQA. Also converts GQA models to MLA in practice.
- **MHA2MLA: Enabling DeepSeek's MLA in Any Transformer-based LLM** (Ji et al., ACL 2025). [arXiv:2502.14837](https://arxiv.org/abs/2502.14837). Converts a model by removing RoPE from some dimensions and applying a joint SVD to the K/V weights. Reduces Llama-2-7B's KV cache by about 92% with only a small drop on long-context tasks.
- **Hardware-Efficient Attention for Fast Decoding (GTA / GLA)** (Zadouri et al., 2025). [arXiv:2505.21487](https://arxiv.org/abs/2505.21487). GTA matches GQA's quality with about half the cache. GLA matches MLA's quality and is easier to split across GPUs with tensor parallelism.
- **Multi-Head Low-Rank Attention (MLRA)** (ICLR 2026). [arXiv:2603.02188](https://arxiv.org/abs/2603.02188). MLA's single latent head cannot be split across GPUs under tensor parallelism. MLRA uses latents that can, and reports about 2.8× faster decoding than MLA.
- **Tensor Product Attention (TPA)** (Zhang et al., NeurIPS 2025). [arXiv:2501.06425](https://arxiv.org/abs/2501.06425). Factorizes Q, K and V into low-rank pieces that depend on the token. MHA, MQA and GQA are the special cases where the factors don't depend on the token. Works with RoPE directly.

### 4. Fewer layers in the cache

- **Cross-Layer Attention (CLA)** (Brandon et al., 2024). [arXiv:2405.12981](https://arxiv.org/abs/2405.12981). Adjacent layers share one KV cache, about 2× smaller than plain MQA with nearly the same accuracy.
- **YOCO: You Only Cache Once** (Sun et al., NeurIPS 2024). [arXiv:2405.05254](https://arxiv.org/abs/2405.05254). The first half of the model (an efficient-attention "self-decoder") produces one global KV cache. The second half reuses it through cross-attention.

### 5. Fewer tokens (eviction and sparse attention)

- **StreamingLLM: Attention Sinks** (Xiao et al., 2023). [arXiv:2309.17453](https://arxiv.org/abs/2309.17453). Keeps the first few "sink" tokens plus a sliding window, which allows streaming generation with constant memory.
- **H2O: Heavy-Hitter Oracle** (Zhang et al., 2023). [arXiv:2306.14048](https://arxiv.org/abs/2306.14048). Keeps the tokens that have received the most attention so far, plus recent tokens.
- **SnapKV** (Li et al., NeurIPS 2024). [arXiv:2404.14469](https://arxiv.org/abs/2404.14469). Before generation starts, uses attention from a window at the end of the prompt to decide which prompt KV entries to keep.
- **Native Sparse Attention (NSA)** (Yuan et al., DeepSeek, 2025). [arXiv:2502.11089](https://arxiv.org/abs/2502.11089). Three branches (compressed tokens, selected token blocks, a sliding window) with kernels designed for the hardware. Trained sparse from the start.
- **MoBA: Mixture of Block Attention** (Lu et al., Moonshot, 2025). [arXiv:2502.13189](https://arxiv.org/abs/2502.13189). Each query is routed to its top-k KV blocks, the way mixture-of-experts routes tokens. Can switch between full and sparse attention.
- **DeepSeek-V3.2 (DeepSeek Sparse Attention, DSA)** (2025). [arXiv:2512.02556](https://arxiv.org/abs/2512.02556). A lightweight indexer picks the top-k KV entries for each query. Built on top of MLA.
- *Note:* sparse attention usually reduces how much of the cache is *read* per step, not how much is *stored*.

### 6. Fewer bits

- **KIVI** (Liu et al., 2024). [arXiv:2402.02750](https://arxiv.org/abs/2402.02750). 2-bit KV cache that needs no tuning. Keys are quantized per channel and values per token.
- **KVQuant** (Hooper et al., NeurIPS 2024). [arXiv:2401.18079](https://arxiv.org/abs/2401.18079). Quantizes keys per channel *before* RoPE is applied, uses non-uniform levels, and keeps outliers separately at higher precision.

### 7. Memory management and serving

- **PagedAttention / vLLM** (Kwon et al., SOSP 2023). [arXiv:2309.06180](https://arxiv.org/abs/2309.06180). The KV cache is split into blocks and located through a block table, so it doesn't need contiguous memory.
- **SGLang / RadixAttention** (Zheng et al., 2023). [arXiv:2312.07104](https://arxiv.org/abs/2312.07104). A radix tree over cached prefixes lets requests with a shared prompt prefix reuse the same KV cache.
- **DistServe** (Zhong et al., OSDI 2024). [arXiv:2401.09670](https://arxiv.org/abs/2401.09670). Runs prefill (compute-bound) and decode (memory-bound) on separate GPUs and moves the KV cache between them.
- **Mooncake** (Qin et al., 2024). [arXiv:2407.00079](https://arxiv.org/abs/2407.00079). The serving system behind Kimi. Pools the KV cache across the CPU, DRAM and SSD of a GPU cluster and schedules around it.
- **FlashInfer** (Ye et al., MLSys 2025). [arXiv:2501.01005](https://arxiv.org/abs/2501.01005). Represents KV-cache layouts in a block-sparse format, compiles attention variants just-in-time, and combines partial results with the attention-state ⊕ (the monoid in §0).

### 8. IO-aware exact attention (the FlashAttention family)

- **Online normalizer calculation for softmax** (Milakov & Gimelshein, 2018). [arXiv:1805.02867](https://arxiv.org/abs/1805.02867)
- **Self-attention Does Not Need O(n²) Memory** (Rabe & Staats, 2021). [arXiv:2112.05682](https://arxiv.org/abs/2112.05682). Chunked attention with online softmax, O(√n) memory.
- **FlashAttention** (Dao et al., 2022). [arXiv:2205.14135](https://arxiv.org/abs/2205.14135). Tiles held in SRAM, plus recomputation in the backward pass. Exact, O(N) memory.
- **FlashAttention-2** (Dao, 2023). [arXiv:2307.08691](https://arxiv.org/abs/2307.08691)
- **Flash-Decoding** (Dao et al., 2023, [blog post](https://crfm.stanford.edu/2023/10/12/flashdecoding.html)). Splits the KV cache along the sequence and combines the pieces with ⊕. This matters when decoding with small batches.
- **FlashDecoding++** (Hong et al., MLSys 2024). [arXiv:2311.01282](https://arxiv.org/abs/2311.01282). Asynchronous softmax using a shared maximum, plus optimized GEMMs for the thin matrices that appear in decoding.
- **FlashAttention-3** (Shah et al., 2024). [arXiv:2407.08608](https://arxiv.org/abs/2407.08608). For Hopper GPUs: asynchronous execution, warp specialization, FP8.
- **FlexAttention** (Dong et al., 2024). [arXiv:2412.05496](https://arxiv.org/abs/2412.05496). You write a `score_mod` / `block_mask` in PyTorch and it is compiled into fused, block-sparse kernels.
- **SageAttention** (Zhang et al., ICLR 2025). [arXiv:2410.02367](https://arxiv.org/abs/2410.02367). INT8 for QKᵀ after smoothing K, and FP16 with an FP16 accumulator for PV. About 2× faster than FlashAttention-2.
- **FlashAttention-4** (Zadouri, Hoehnerbach, Shah, Liu, Thakkar, Dao, 2026). [arXiv:2603.05451](https://arxiv.org/abs/2603.05451). For Blackwell GPUs: fully asynchronous matrix-multiply pipelines, exponentials computed in software, and softmax rescaling only when needed. Written in CuTe-DSL.
- **Ring Attention** (Liu et al., 2023). [arXiv:2310.01889](https://arxiv.org/abs/2310.01889). Spreads blockwise attention over devices arranged in a ring, overlapping the transfer of KV blocks with computation.

### 9. Contrast: approximate, sub-quadratic attention

- **Sparse Transformer** (Child et al., 2019). [arXiv:1904.10509](https://arxiv.org/abs/1904.10509). Fixed sparsity patterns.
- **Longformer** (Beltagy et al., 2020). [arXiv:2004.05150](https://arxiv.org/abs/2004.05150). Sliding window plus a few global tokens.
- **Linformer** (Wang et al., 2020). [arXiv:2006.04768](https://arxiv.org/abs/2006.04768). Low-rank projection along the sequence dimension.
- **Transformers are RNNs (Linear Attention)** (Katharopoulos et al., 2020). [arXiv:2006.16236](https://arxiv.org/abs/2006.16236). Replaces softmax with a kernel feature map, which gives a recurrent form.
- **Performer** (Choromanski et al., 2020). [arXiv:2009.14794](https://arxiv.org/abs/2009.14794). Approximates the softmax kernel with random features (FAVOR+).
- **Mistral 7B** (Jiang et al., 2023). [arXiv:2310.06825](https://arxiv.org/abs/2310.06825). Sliding-window attention with a rolling KV buffer, combined with GQA.

### 10. Related: speculative decoding

Speculative decoding attacks the same memory-bandwidth limit from a different direction: it does more useful work per pass over the weights.

- **Fast Inference from Transformers via Speculative Decoding** (Leviathan et al., 2022). [arXiv:2211.17192](https://arxiv.org/abs/2211.17192)
- **Accelerating LLM Decoding with Speculative Sampling** (Chen et al., 2023). [arXiv:2302.01318](https://arxiv.org/abs/2302.01318)
- **Medusa** (Cai et al., 2024). [arXiv:2401.10774](https://arxiv.org/abs/2401.10774). Adds extra decoding heads and verifies their guesses with tree attention.
